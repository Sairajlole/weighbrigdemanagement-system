# Email design mockups

High-fidelity **design mockups** for a future email redesign, taking direction
from the app's **welcome page**:

- **Light mode** — white cards on a light tinted page, dark text (matches the
  app's light theme tones).
- **Wordmark-only header** — `tulanam`, all-lowercase, **Inter** weight 800,
  letter-spacing 2 (as `welcome_step.dart`). No logo mark in the header.
- **Background** — the logo **tiled in a spaced, faint-teal grid** (a frozen
  frame of the drifting `LogoWatermarkBg` watermark; `logo_tile.png` is a padded
  transparent tile so the logos have real spacing).
- **Font** — Inter throughout.
- **Company details** band in every template (tenant: name, GSTIN, PAN, address, phone, email).
- **"This is an automated message — please do not reply."** + **tulanam.com** in every footer.
- **Receipt** is **placeholder-driven** (mirrors the printing tokens `{rst}`,
  `{vehicle}`, `{gross}`/`{tare}`/`{net}`, `{material}`, `{operator}`, `{customer_*}`,
  `{company_*}`, …) and renders **only fields that have data**. Structure:
  1. **Customer = primary card** at top (large square photo) + RST number + status.
  2. Vehicle, then **net / gross / tare** weights with timestamps.
  3. **Operator** (small circular avatar) + weighment details.
  4. After the operator, details are **strictly the printer template-line fields**
     (`{weighbridge_name}`, `{port_name}`; `{pc_name}` is grouped with the operator,
     as in the printer's group 7) — no invented extras.
  5. **Custom fields** are appended automatically when the weighment has any.
  6. **CCTV snapshots** in two columns — **Tare | Gross, up to 3 each**, each frame
     strictly **16:9** — only the ones present are rendered.
  7. **Real PDF417** barcode (generated by `bwip-js`, `genbc.js` → `pdf417.png`) at
     the printed **1:5** ratio. The RST is shown **without an "RST-" prefix** (just
     the number).
- **Report** has **no attachment row** — the full-day detailed report rides along as
  a real **email attachment**, so it isn't depicted inside the body.
- **Report** adds a **weighments-by-hour** chart and an **attachment chip** (the
  full-day detailed report ships as a PDF attachment); meant as a generic report
  usable for every instance for now.
- PNGs are **trimmed to the card** (consistent canvas, no padding overshoot).

All rendered to PNG from full modern CSS (gradients, glass, gradient-clipped
numerals, real bar chart, QR) — none of which survives raw email HTML, which is
why production renders the design to an **image** server-side.

| File | Template |
|------|----------|
| `otp.png` / `otp.html` | OTP — glassy gradient code card |
| `receipt.png` / `receipt.html` | Weighment receipt — digital ticket (with QR of the ticket ID) |
| `report.png` / `report.html` | Daily report — KPI tiles + materials bar chart |
| `logo.png` | brand mark (so the HTML renders standalone) |

> Open the `.html` files locally to tweak; they reference `logo.png` and load
> Inter from Google Fonts (needs network).

## How these are rendered (`render.js`)
Rendered with **Puppeteer (`puppeteer-core`) screenshotting the `.wrap` element
directly** — not a fixed window + crop. Element screenshots capture the exact
card bounds at natural height, so there's no window-size guessing, no
ImageMagick trimming, and no blank space / clipped borders. Setup:

```
npm i puppeteer-core        # uses the installed Chrome, no Chromium download
node render.js              # screenshots .wrap of each *.html → png
```

Card width is set by the viewport (704 css = ~600 card + margins) at
deviceScaleFactor 2 for retina-crisp output.

## Status
- **Mockups only** — not wired into the app. Live email code remains in
  `functions/index.js` (`buildOtpEmail` / `buildBrandEmail`); test sender is
  `functions/_test_emails.js`.

## Production direction (if approved)
1. Render each design to PNG server-side (recommended: **Satori + resvg** in a
   Cloud Function) from real field + company data.
2. Host via Firebase Storage with **short-lived signed URLs** (or inline CID) for
   sensitive emails (OTP, receipts).
3. **Hybrid, never image-only:** repeat critical data (OTP code, links, key
   figures) as live HTML text/links beneath the image, so it survives image
   blocking and stays accessible/searchable.
4. Test matrix: Gmail, Outlook desktop, Apple Mail, iOS/Android — incl. images blocked.
